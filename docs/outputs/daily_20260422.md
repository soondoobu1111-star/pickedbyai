## 🎯 교훈 (영구 기록)

1. **Cron 표현식 충돌 = silent failure** — 여러 cron이 동일 순간에 매칭되면 CF Workers는 한 값만 event.cron에 전달. 이벤트 당 하나의 분기만 실행 → 다른 스케줄 누락. **해결 원칙: cron 표현식 간 1분 이상 오프셋 필수.**
2. **"승인 사항"도 검증 없이 믿지 마라** — 어제 "내일 KST 00:00 cron 검증 승인"이 당연히 실행될 거라 가정했음. 새 세션 시작 시 가장 먼저 검증해야 할 것은 **전 세션에서 약속된 자동 작업의 실제 실행 여부**.
3. **logProbes는 non-blocking으로 설계된 것이 축복** — 만약 probe_logs insert 실패가 throw였다면 cron 전체 abort. 에러 로그만 남기는 설계 덕분에 scores insert는 진행됐을 것. **하지만 오늘 cron이 실행 안 된 건 이와 무관 — cron 충돌이 진짜 원인.**
4. **"전제를 뒤엎는 검증"** (빅파이 1.5 §15 교훈 #7) — 처음엔 probe_logs 누락을 cron 실패 원인으로 의심. 수동 트리거 성공으로 가설 기각. 표면 증상(probe_logs 누락)과 진짜 원인(cron 충돌)을 분리해내는 과정 가치.
