## [CPO] 세션 5 — kitty keyboard protocol 영구 수정 (데스크탑 Claude, KST)

### 트리거
CEO 스크린샷: 터미널에서 `claude3u27u27u` 문자 재발. 이전 수정(`\033[>0u`) 적용에도 불구하고 3회째 재발.

### 근본 원인 조사 결과
| 계층 | 원인 |
|---|---|
| Claude Code | 시작 시 `\033[>1u`로 kitty keyboard protocol push → 종료 시 pop 실패 (비정상 종료/signal/crash) |
| 기존 수정 | `\033[>0u`는 **flags 리셋**일 뿐 **스택 pop이 아님** → 스택에 push 잔여 → 재발 |
| 셸 | bash가 kitty-encoded keypress(`\033[3u`, `\033[27u`)를 이해 못 함 → 텍스트로 출력 |

### 영구 수정 (3중 방어)
`~/.bash_profile` 교체:

```bash
_kitty_kbd_reset() {
  printf '\033[<99u\033[=0u' 2>/dev/null || true
}
_kitty_kbd_reset                          # 셸 시작 시
claude() {                                # wrapper
  command claude "$@"
  local rc=$?; _kitty_kbd_reset; return $rc
}
PROMPT_COMMAND="_kitty_kbd_reset;${PROMPT_COMMAND:-}"  # 매 프롬프트
```

| 방어 계층 | 시퀀스 | 이전 수정과 차이 |
|---|---|---|
| `\033[<99u` | 스택 99단계 drain (pop all) | 이전 `\033[>0u`는 pop 아님 |
| `\033[=0u` | flags hard-disable | 이전은 soft reset |
| `PROMPT_COMMAND` | SIGKILL/crash 후 자동 복구 | 이전은 wrapper만 존재 |
