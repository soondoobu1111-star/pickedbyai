### RETRY 아키텍처
```
온보딩 직후 /v1/domains/verify 성공
  ↓ ctx.waitUntil()
첫 자동 체크 (runInternalCheck)
  ├─ fully_successful → retry_state=null, tier_0 (완료)
  ├─ partial (일부 엔진 성공) → tier_1, 다음 attempt 예약
  └─ 전체 실패 → tier_1, attempt_count=1, next_attempt_at=now+60s

매 1분 cron (* * * * *)
  ├─ fetchDueRetries(20) — next_attempt_at ≤ now 필터
  ├─ runInternalCheck 순회
  ├─ 성공 → queue 탈출 (tier_0 or tier_1)
  ├─ 실패 + attempt<5 → 다음 회차 예약
  └─ 실패 + attempt=5 → 소진 → Tier 2 (스냅샷 유지) or Tier 3 (연속 3일+ stale)
```
